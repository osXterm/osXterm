# 인증 정보 처리

osXterm은 연결 프로필을 사용자 설정 디렉터리에 저장하고, 사용자가 선택한 경우에만 비밀번호를 AES-GCM으로 암호화해 프로필 설정에 보관한다.

## 저장 위치

- 연결 프로필: `~/.config/osXterm/profiles.json`
- 암호화 키: `~/.config/osXterm/.password-key`

프로필 디렉터리는 권한 0700, 프로필 파일은 권한 0600으로 생성된다. 이전 버전의 설정 위치에 프로필과 암호화 키가 있고 새 파일이 없으면 첫 실행 때 `~/.config/osXterm/`으로 이전한다.

## 프로필에 저장되는 정보

- 연결 이름, 호스트, 포트, 사용자 이름
- 인증 방식
- 선택한 SSH agent 소켓 경로
- 선택한 개인 키 파일 경로
- JumpHost 설정

프로필 JSON에는 평문 비밀번호를 저장하지 않는다. 저장을 선택한 프로필에는 `encryptedPassword` AES-GCM 암호문이 들어가며, 암호화 키 파일은 권한 0600으로 생성된다.

## 비밀번호 연결

비밀번호 인증 프로필을 등록하거나 연결하면 앱이 네이티브 보안 입력창을 표시한다. 등록 화면에 비밀번호를 입력하면 AES-GCM으로 암호화해 프로필 JSON에 저장할 수 있다. 연결 시 저장된 암호문을 복호화하며, 저장하지 않은 입력값은 활성 세션이 유지되는 동안에만 메모리에 보관된다.

OpenSSH가 AskPass 값을 요청할 때 앱은 권한 0700의 임시 디렉터리에 만든 세션 전용 Unix-domain socket으로 복호화한 값을 전달한다. 소켓 자체는 권한 0600이며, 환경 변수에는 비밀번호가 아니라 임의의 소켓 경로만 전달된다. 세션이 끝나거나 연결 시작에 실패하면 소켓과 메모리 값을 즉시 폐기한다.

## 개인 키

osXterm은 개인 키의 암호문을 저장하거나 입력받지 않는다. 암호화된 개인 키는 Bitwarden SSH Agent 또는 다른 호환 SSH agent에 로드한 뒤 SSH Agent 인증 방식으로 연결한다.

## 기존 프로필

이전 버전이 저장한 비밀번호 참조값이 포함된 프로필은 비밀번호 인증 프로필로만 마이그레이션된다. 프로필을 읽을 때 참조값은 제거되어 다시 저장되며, 다음 연결에서 비밀번호를 다시 입력하거나 등록 화면에서 암호화 저장해야 한다.
