# osXterm 사용 가이드

osXterm은 여러 SSH 서버를 한 작업 공간에서 관리하는 macOS 앱입니다. 프로필, 터미널, 파일 전송, 터널은 한 SSH 경로와 인증 정책을 공유합니다. 이 문서는 현재 구현된 동작을 설명합니다. Release 앱과 DMG의 최종 실행 검증 상태는 [TESTING.md](TESTING.md)와 [GOAL_STATUS.md](../GOAL_STATUS.md)를 기준으로 확인하세요.

## 시작하기

1. 왼쪽 탐색 영역에서 새 연결을 선택합니다.
2. 프로필 이름, 호스트, 사용자, 포트와 인증 방식을 입력하고 저장합니다.
3. 저장된 프로필을 선택해 연결합니다. 탭이 열리고 OpenSSH 인증과 host key 확인이 끝난 뒤에만 연결됨으로 표시됩니다.
4. 같은 서버에 별도 셸이 필요하면 터미널 헤더의 세션 추가 버튼이나 Session 메뉴의 같은 프로필로 SSH 세션 추가를 사용합니다. 각 실행은 독립 프로세스와 독립 자격 증명 broker를 사용합니다.

로컬 셸은 툴바의 로컬 터미널 또는 Shift-Command-T로 열 수 있습니다. 새 연결은 Command-N으로 시작할 수 있습니다.

## 연결 프로필과 인증

프로필은 호스트명, IPv4, IPv6, 사용자 지정 포트, keepalive, 연결 시간 제한, 재연결 정책, jump host, 프록시, 포트 포워딩 규칙을 가집니다. 비밀 값은 일반 설정 파일이나 프로필 내보내기에 기록하지 않습니다.

지원하는 인증 방식은 다음과 같습니다.

- SSH agent와 사용자 지정 agent socket
- 개인키와 암호화된 개인키
- 비밀번호
- OpenSSH 사용자 인증서
- keyboard-interactive 질문과 다단계 질문

암호, passphrase, 프록시 비밀번호와 keyboard-interactive 응답은 macOS Keychain 참조로 관리합니다. 앱과 AskPass 및 프록시 helper 사이에는 세션별 Unix-domain socket broker가 사용되므로 비밀을 명령줄, 환경 변수, 로그에 넣지 않습니다.

첫 연결의 host key는 fingerprint를 확인한 뒤 승인합니다. 변경된 host key는 연결을 차단하고 별도 재검토를 요구합니다. agent forwarding은 프로필별 선택이며 기본값은 꺼져 있습니다.

## Jump host와 프록시

Jump host는 저장된 다른 프로필을 순서대로 참조합니다. 각 hop은 별도의 사용자, 포트, 인증 방식, 개인키, agent, 인증서를 가질 수 있습니다. 프로필 저장 전에 순환 참조, 삭제된 참조, 올바르지 않은 경로를 검사합니다.

프록시는 HTTP CONNECT와 SOCKS5를 지원하며, 인증 없는 경우와 사용자명 및 비밀번호 인증을 모두 처리합니다. SOCKS5는 대상 호스트 이름을 프록시에서 해석하도록 전달합니다. 직접 연결, 프록시만 사용하는 연결, 다단계 jump, 프록시와 jump 조합 모두 같은 경로 컴파일러를 통과합니다.

## 터미널 작업 공간

탭 막대에서 세션을 선택하고 이름 변경, 복제, 순서 변경, 닫기를 할 수 있습니다. 작업 공간은 단일 패널, 가로 분할, 세로 분할을 지원하며 현재 탭과 레이아웃 메타데이터를 저장합니다. 앱을 다시 열어도 종료된 원격 셸이 복구된 것처럼 표시하지 않습니다.

| 작업 | 방법 |
| --- | --- |
| 탭 닫기 | Command-W 또는 탭의 닫기 버튼 |
| 같은 프로필의 새 SSH 세션 | Shift-Command-R 또는 세션 추가 버튼 |
| 단일 패널 | Shift-Command-1 |
| 가로 분할 | Shift-Command-2 |
| 세로 분할 | Shift-Command-3 |
| 터미널 검색 | 터미널 헤더의 돋보기 버튼 |

검색은 SwiftTerm의 실제 터미널 버퍼에서 수행합니다. 검색 막대에서 이전, 다음, 대소문자 구분, 정규식, 단어 단위 옵션을 사용할 수 있습니다.

설정의 터미널 탭에서 글꼴 크기와 줄 간격을 조정하고, 20개 테마를 선택할 수 있습니다. 글꼴은 시스템 글꼴 목록에 의존하지 않고 앱에 포함된 D2 Coding, JetBrains Mono, Fira Code, Hack만 사용합니다. 설정 화면의 미리보기는 선택한 글꼴과 테마의 실제 터미널 팔레트를 표시합니다.

## 동시 입력

오른쪽 검사기의 연결 정보 섹션에서 두 개 이상의 연결된 세션을 선택하면 동시 입력이 활성화됩니다. 체크된 세션에서 입력한 내용만 다른 체크된 준비 완료 세션으로 전달합니다. 체크되지 않은 세션의 입력은 다른 세션으로 보내지지 않습니다.

연결된 세션 모두 선택 버튼은 현재 연결된 세션을 명시적으로 대상으로 지정합니다. 끄기 버튼은 선택을 모두 해제합니다. 세션이 연결 해제되거나 인증 실패 상태가 되면 대상에서 자동으로 제외되며, 재연결 후에는 다시 선택해야 합니다.

## 터널과 포트 포워딩

터널 패널에서 로컬, 원격, dynamic SOCKS, remote dynamic, 로컬 Unix socket, 원격 Unix socket 규칙을 만들고 시작, 중지, 재시작할 수 있습니다. 여러 규칙을 동시에 실행할 수 있으며, 터미널 세션에 연결하거나 독립 터널로 실행할 수 있습니다.

새 규칙은 loopback bind 주소를 기본값으로 사용합니다. 외부 인터페이스 노출은 사용자가 주소를 명시적으로 바꿀 때만 요청됩니다. 원격 포트 0을 요청한 경우 서버가 할당한 포트를 표시합니다.

터널의 listener 생성과 대상 서비스 접근은 별도 상태입니다. listener가 준비된 뒤 대상 확인을 실행해 실제 도달 여부를 확인합니다. 독립 터널은 창이 닫힌 뒤에도 메뉴 막대 항목에서 상태 확인과 중지를 할 수 있으며, 앱 종료를 확정하면 앱이 시작한 프로세스를 정리합니다.

## 파일 전송과 원격 편집

SSH 세션을 선택하면 오른쪽 파일 전송 패널에서 SFTP를 사용할 수 있습니다. 경로 직접 입력, 새로 고침, 숨김 파일 표시, 업로드, 다운로드, Finder 선택, 드래그 앤드 드롭, 폴더 생성, 이름 변경, 삭제, 권한 변경을 지원합니다. 목록은 사람이 읽는 `ls` 출력이 아니라 SFTP v3 구조화 메시지로 읽습니다.

전송 큐는 진행률, 취소, 실패, 재시도를 표시합니다. 충돌 시 덮어쓰기, 건너뛰기, 이름 변경 중 하나를 명시적으로 고릅니다. 단일 파일 SFTP 재개는 원본 메타데이터와 이미 전송된 prefix의 SHA-256을 확인한 뒤에만 이어서 전송합니다. 재귀 SFTP와 SCP 전송은 현재 재시도 시 처음부터 다시 시작합니다.

원격 일반 파일은 로컬 편집기로 열 수 있습니다. 변경한 파일은 저장 후 원격에 저장을 명시적으로 선택해야 다시 업로드됩니다. SCP도 같은 경로와 인증 정책을 사용하며 SFTP 전송 모드로 실행됩니다.

## 프로필 가져오기와 반복 작업

프로필에는 폴더, 태그, 즐겨찾기, 최근 연결을 사용할 수 있습니다. SSH config 가져오기는 미리보기에서 Host, Include, wildcard와 지원되는 인증 및 경로 옵션을 보여 줍니다. 미리보기는 Match exec나 ProxyCommand를 실행하지 않습니다. 내보내기에는 Keychain 참조만 포함되고 비밀 값은 포함되지 않습니다.

명령 스니펫은 명령 순서와 변수 입력을 저장합니다. 실행은 항상 사용자의 명시적 동작으로 시작하며, 작업 공간 복원 시 스니펫이나 매크로가 자동 실행되지 않습니다. broadcast 대상이 선택되어 있으면 스니펫도 그 세션 집합에만 보냅니다.

## 세션 로그와 클립보드

세션 로그는 설정에서 사용자가 켜야 합니다. 로그에는 터미널 입출력과 해당 세션으로 전달된 동시 입력 및 스니펫 입력이 포함될 수 있으므로 민감한 명령이나 응답이 기록될 수 있습니다. 내보내기 전 저장 위치와 공유 대상을 확인하세요. 로그 파일은 Application Support 아래의 private 권한으로 관리되고, 내보내기는 사용자가 선택한 위치로만 수행됩니다.

OSC 52 원격 클립보드 접근은 기본 차단입니다. 필요한 경우에만 설정의 보안 탭에서 허용하세요. 허용하면 원격 프로그램이 시스템 클립보드를 읽거나 쓸 수 있습니다.

## 문제 해결

- 인증이 끝나기 전에는 프로세스가 실행 중이어도 연결됨으로 표시되지 않습니다. 연결 단계와 오류 메시지를 확인하세요.
- host key가 변경되었다면 자동으로 신뢰하지 않습니다. fingerprint를 검토하고 승인 여부를 결정하세요.
- 터널이 listener 상태여도 대상 서비스가 접근 가능한 것은 아닙니다. 대상 확인 결과를 별도로 보세요.
- 파일 전송이나 터널이 실패하면 프로필의 연결 경로, 인증 방식, forwarding 정책, 프록시 자격 증명을 확인하세요.
- 패키지 생성, Docker 통합 검증, DMG에서 꺼낸 앱의 실제 UI 검증 상태는 [TESTING.md](TESTING.md)를 확인하세요.

## 현재 검증 제한

이 작업 환경에서는 Xcode 라이선스가 아직 승인되지 않았고 Docker Compose가 설치되어 있지 않습니다. 따라서 `swift test`, Docker 기반 통합 테스트, Release 앱 빌드, DMG 생성과 추출 앱 검증은 아직 통과로 기록되지 않았습니다. 로컬 패키지 생성이 가능한 환경에서는 먼저 `Scripts/check-environment.sh`를 실행하고, 전체 검증 전에는 `Scripts/check-environment.sh --integration`을 실행하세요. 그 뒤 README의 빌드 절차와 `Scripts/verify.sh`를 실행한 뒤 [TESTING.md](TESTING.md)의 사람 검증 항목까지 수행하세요.
